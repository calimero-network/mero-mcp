Tools fall into four groups. **Core** and **application** tools are always
registered; **blobs** and **governance** are toolsets that can be trimmed with
[`CALIMERO_MCP_TOOLSETS`](/reference/configuration/#toolsets).

<Aside type="note">
These are the server-side names. An MCP client may expose them under a prefix of its
own — commonly `mcp__<server>__<tool>`, so `node_status` becomes
`mcp__calimero__node_status`.
</Aside>

Read-only tools are annotated `readOnlyHint`; destructive ones `destructiveHint`.

## Core

Always registered, regardless of `CALIMERO_MCP_TOOLSETS`.

### `node_status`

Health and identity of the connected node. No arguments. Read-only.

Returns node `health`, the `url` and `nodeName` in use, the
[`discoverySource`](/understand/node-discovery/), and the [`authMode`](/understand/authentication/).
`nodeName` is `null` when nothing on this machine names the node.

A node that was unreachable at connect is not an error until a tool needs it, so this is usually the first call to report it,
which makes it the right first call of a session.

### `list_nodes`

Nodes known on this machine, merged with a live local probe. No arguments. Read-only.

Each entry is `{ url, name, active }`. `name` is `null` for a node found only by
probe. `active: true` marks the one this session is using.

### `list_applications`

Applications installed on this node. No arguments. Read-only.

Application `metadata` rides the wire as raw bytes; it is decoded for display into
the JSON object it usually encodes, or the plain string, or omitted — never dumped as
a byte array.

Each entry also carries `appVersion` and `procedures`: the `###` titles under `## Procedures` in the app's guide, or `[]` when it ships none.
The guide itself is left out; `describe_app` returns it.

### `list_namespaces`

Namespaces on this node. No arguments. Read-only.

### `list_contexts`

Contexts on this node. Read-only.

| Argument | Type | Notes |
| --- | --- | --- |
| `application` | string, optional | Filter to one application |

`dagHeads` are rendered as hex.

### `create_context`

Create a context for an application under a namespace.

| Argument | Type | Notes |
| --- | --- | --- |
| `application` | string | Id, package name, or unambiguous trailing segment |
| `namespace` | string | Namespace id |
| `name` | string, optional | |
| `service` | string, optional | Required for a multi-service application |

### `delete_context`

Delete a context and its data. **Destructive.**

| Argument | Type | Notes |
| --- | --- | --- |
| `context` | string | Context id or alias |

Also the fix for a context stranded by deleting its namespace first — those contexts
outlive the namespace and stay uncallable until removed.

### `create_alias`

Create a human-friendly alias for a context id.

| Argument | Type |
| --- | --- |
| `alias` | string |
| `contextId` | string |

### `lookup_alias`

Resolve a context alias to its id. Read-only.

| Argument | Type |
| --- | --- |
| `name` | string |

A miss returns `No alias named "…" on this node.` as a **result**, not an error.

## Blobs

In `CALIMERO_MCP_TOOLSETS` by default. Application bytecode is a blob, which is why
install/uninstall live here.

### `install_application`

Install a published application from the node's own configured registry, by
`package@version` coordinates.

| Argument | Type | Notes |
| --- | --- | --- |
| `coords` | string | `package@version`, e.g. `com.example.myapp@1.0.0` |

### `uninstall_application`

**Destructive.** Takes `application` (id, package, or trailing segment).

### `upload_blob`

| Argument | Type | Notes |
| --- | --- | --- |
| `data` | string | Base64-encoded blob bytes |
| `hash` | string, optional | |
| `context` | string, optional | Scope the blob to a context |

### `list_blobs`

Blobs stored on this node. No arguments. Read-only.

### `delete_blob`

**Destructive.** Takes `blob` (blob id).

## Governance

In `CALIMERO_MCP_TOOLSETS` by default.

### `create_namespace`

| Argument | Type | Notes |
| --- | --- | --- |
| `application` | string | Id, package name, or trailing segment |
| `name` | string, optional | |

### `delete_namespace`

**Destructive.** Takes `namespace`.

Its contexts **outlive it** and stay uncallable until `delete_context` removes them —
delete contexts first. See [contexts and namespaces](/guides/contexts-and-namespaces/#deleting-things-in-the-right-order).

### `invite_to_namespace`

Mint an invitation. Takes `namespace`. Returns the invitation object.

### `join_namespace`

| Argument | Type | Notes |
| --- | --- | --- |
| `namespace` | string | |
| `invitation` | object | The object `invite_to_namespace` returned, **unchanged** |
| `groupName` | string, optional | |

<Aside type="caution">
The invitation is signed over its own bytes. Reshaping it — renaming keys, dropping
fields — invalidates the signature. The server declares it as an opaque object so
validation cannot strip fields it does not know about; pass it straight through.
</Aside>

### `leave_namespace`

**Destructive.** Takes `namespace`.

### `list_group_members`

Members of a group. Read-only. Takes `group`. Returns a flat `{ members, selfIdentity? }`.

### `add_group_members`

| Argument | Type |
| --- | --- |
| `group` | string |
| `members` | array of `{ identity, role }` |

## Application

Always registered.

### `describe_app`

Show an application's methods and guide without choosing a context. Read-only.

| Argument | Type | Notes |
| --- | --- | --- |
| `app` | string | Id, package name, or trailing segment |
| `service` | string, optional | For an app bundling several services |

Returns, as JSON: `application`, `package`, `appVersion`, resolved `service`, `contextServices`, every method as a signature, and an `app_handle` with no context.
Then the guide as an embedded `text/markdown` resource after an author label, or the line `This app ships no guide.`

Omitting `service` on a multi-service app returns an error naming the available services.
When no context exists to read a service name from, a `serviceNote` says so: nothing on the application record or in the ABI lists an app's services.

### `select_app`

Choose an application and the context to act in. Read-only.

| Argument | Type | Notes |
| --- | --- | --- |
| `app` | string | Id, package name, or trailing segment |
| `context` | string, optional | Context id or alias; defaults to the app's only context |
| `service` | string, optional | Only when no context is chosen; a chosen context decides the service |

Returns everything `describe_app` does, plus the app's tool names (`tools`), the chosen `context`, and an `app_handle` bound to that context and its service.
`tools` lists exactly the tools of the app and service the handle binds.
When a package name matches apps from several signers, `select_app` and `describe_app` refuse and list each application id with its signer; pass the application id.
For a bundle with one named service, a context created without a service name binds that service.
With several contexts and none chosen, `context` is `null` and a `note` lists the ids.
An app missing from the tool list, for example because the node was down at connect, makes `select_app`, `describe_app` and `call` read the list again first.

### `call`

Call an application method by name.

| Argument | Type | Notes |
| --- | --- | --- |
| `app_handle` | string | From `select_app` |
| `method` | string | ABI method name |
| `args` | object, optional | Arguments keyed by parameter name |
| `app` | string, optional | Shows that app's guide on a refusal; a handle for another app is refused |

An unknown `method` returns the list of methods that exist.

## Generated method tools

One per method of every installed application, sorted by package, then application id, then service, then method, for every client alike.
Named `<app>_<method>`, or `<app>_<service>_<method>` for a multi-service application, where `<app>` is the sanitised trailing package segment cut to 20 characters; a name longer than 49 characters keeps its first 42 and ends in `_` plus 6 hex of its sha256.
A name never repeats a fixed tool's name or another app's: a clash adds `_` plus 6 alphanumerics of the application id (see [tool naming](/reference/abi-mapping/#tool-naming)).

| Argument | Type | Notes |
| --- | --- | --- |
| `app_handle` | string | From `select_app`; names the context |

plus the method's declared parameters, typed from the ABI ([ABI mapping](/reference/abi-mapping/)).

Each tool carries a `title` (`Set blocks (Mero Blocks)`), the method's signature as its `description`, an `outputSchema` when the method returns something, and explicit `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint: false` annotations.
`readOnlyHint` follows the method's intent; the ABI cannot mark a method destructive or idempotent yet, so `destructiveHint` is always `false` and `idempotentHint` equals `readOnlyHint`.
It also carries `icons` when the app's `metadata.icon` is a URL, and `_meta` with the `package`, `appVersion`, `signerId` and method `intent`.
Results carry `structuredContent` next to the JSON text.
A contract call that fails returns `isError: true` with the node's message.

## Resources

`calimero://apps/{applicationId}/{version}/guide` (`text/markdown`): one resource per installed app that ships a guide.
The application id is core's hash of package and signer, so two signers of one package get separate guides; the embedded copy's `_meta` carries `package`, `appVersion` and `signerId`.
